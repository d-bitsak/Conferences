# Личная конфигурация и подключения

Проводить первый запуск по first-run.md. Использовать assets/config.example.json как пустой пример; не менять его реальными данными. Для чтения источников и хранения тренировочных/здоровьевых данных применять точную область команды владельца.

## Параметры

| Параметр | Правило |
| --- | --- |
| mode | REVIEW для нового подключения; ACTIVE только для разрешённых и проверенных внешних действий |
| owner_ref | Проверенная личность/контекст владельца; не наследовать автора скилла |
| timezone | Подтверждённая IANA-зона; null не означает UTC или зону сервера |
| profile | Цель, опыт, частота, время и оборудование из подтверждённых ответов; пустое значение не доказывает отсутствие ограничений |
| sources | Только выбранный план и история; доступ к одному чату не распространяется на остальные |
| diary | Проверенное назначение, фактические вкладки, чтение/запись и подтверждение результата |
| permissions | Отдельные источники разрешений на чтение, запись тренировок, самочувствие, WHOOP/расходы и расписание |
| whoop | Существующее подключение/аккаунт, бюджет и ссылка на кредитное состояние; по умолчанию выключено |
| reservation | Проверенная защита платного сбора от параллельных запусков; обычный read-back JSON/Sheets не доказывает исключительность |
| evening | Реальное локальное время, расписание, дата начала и личный постоянный канал |
| setup_ref | Частный manifest этапов, проверок и блокировок |
| bootstrap_ref | Независимая ссылка в контексте агента и каждого запуска |

Google Sheets использовать как адаптер при подтверждённом доступе; другой дневник допустим с той же семантикой плана/факта и защиты повторов. Схему вкладок и шаблон читать в table-schema.md. Без постоянного дневника доступны программа и текстовый отчёт, но не платный вечерний сбор.

Вкладка «План и настройки» или явно выбранный эквивалент хранит текущий план и его источник, зону, кредитную блокировку, подтверждённый сброс и отметку уведомления. Дневная строка хранит статусы WHOOP-запросов. Считать эти выбранные записи источником истины; в конфигурации держать ссылки, не создавать конкурирующий список метрик/статусов в нескольких файлах.

## Независимое обнаружение

Находить bootstrap_ref сначала в текущем запросе/prompt, затем в зарегистрированном постоянном контексте этого агента и владельца. Bootstrap содержит owner_ref, config_ref, diary_ref и setup_ref. Перечитать ссылки и владельца; противоречащие ссылки не объединять наугад.

Явно переданная владельцем рабочая конфигурация допустима как точка входа при проверке назначения. Ссылка на config внутри дневника и обратная ссылка на дневник внутри config не заменяют независимую точку входа. Если постоянная привязка недоступна, честно указать предел восстановления после новой сессии.

## WHOOP / IFTTT

Проверять доступность инструментов и текущие схемы без платных WHOOP-вызовов. Использовать только существующую штатную авторизацию. Выбирать account_id по подтверждённому подключению; при нескольких/неопределённых аккаунтах уточнить выбор, не просить токены или пароль.

До платных действий согласовать данные, назначение их хранения, максимум попыток и расходы по текущему тарифу. Не считать стоимость фиксированной. Для настройки инициализация нулевого числа результатов и наличие аккаунта не доказывают кредитное состояние; прочитать выбранные настройки и подтвердить сведения о блокировке/сбросе. Не проверять баланс платным вызовом.

Пробный сбор разрешать только по отдельной команде на такой тест. Разрешение на будущий ежедневный отчёт не означает выполнить платную пробу сейчас. Во время любого разрешённого сбора соблюдать evening.md: максимум три прямых попытки, fields={}, без дополнительных поисков и повторов.

Другой провайдер метрик требует отдельного проверенного контракта и области разрешения. Не переносить разрешение IFTTT автоматически.

## Вечерний запуск

Проверить реальный планировщик, IANA-зону, доступ к скиллу/коннекторам/дневнику между запусками и постоянный личный канал. Время 22:00 допустимо предложить, но не назначать автоматически. Установленный скилл сам не является расписанием.

После прямой команды проверить существующие запуски, подготовить нужный без дубля и сохранить bootstrap_ref, область, бюджет и правила остановки в prompt. Перечитать ID, enabled, зону, ближайший запуск и назначение результата. Новые запуски готовить выключенными либо с REVIEW до подтверждения зависимостей; не выключать чужие/неоднозначные.

При изменении существующей настройки сохранять прежние разрешения, историю, credit/unknown и дату начала; не переподключать всё и не запускать историю заново.
