# Подключение и конфигурация

## Первый запуск

Провести диалог по first-run.md и завершить карточкой setup-result.md. Технические проверки выполнять самостоятельно; не просить пользователя выбирать формат журнала или перечислять ID.

Начать с загруженного TXT/VTT/JSON или доступного по разрешённому подключению транскрипта. Для базового анализа достаточно источника; язык брать из запроса, время — из явных метаданных. Не требовать заполнять все настройки.

Прочитать assets/config.example.json как пример, не как действующую конфигурацию. По запросу настройки самостоятельно подобрать проверенное доступное личное хранилище и сохранить рабочие config, state и setup manifest. Уточнять выбор только при реальной неоднозначности владельца, видимости или назначения. Не менять пример в распространяемом скилле и не сохранять в него реальные данные.

Разделять три операции: подготовку текста, разовое внешнее действие и постоянную автоматизацию. Для постоянной работы явно установить дату начала и нужные направления; не переносить старые разрешения автора или предыдущего получателя.

## Поля конфигурации

| Поле | Правило |
| --- | --- |
| schema_version | Использовать 1 для данного формата; мигрировать существующее состояние осознанно |
| mode | REVIEW по умолчанию; ACTIVE только в явно разрешённой области |
| timezone | IANA-зона владельца; UTC в примере — заполнитель, не доказательство зоны встречи |
| language | Язык результата; исходные реплики не переводить при экспорте |
| owner | Имя и ссылки на проверенную личность/профили; имя само по себе не доказывает спикера |
| source | Провайдер/файл и существующее подключение; classify_before_transcript включает проверку до чтения |
| calendar | Реальное подключение и конкретные календари; политика email по умолчанию all_invited |
| authorization | Источник команды, active_since и отдельная политика backfill |
| journal | Устойчивое личное хранилище и проверенная условная запись либо эквивалентный lock |
| setup_ref | Ссылка на личный manifest прогресса и доказательств настройки |
| automation | Отдельные enabled, bootstrap_ref, способ/ID обнаружения и ID/частота повтора очереди; сами поля не создают запуск |
| waiting | Интервалы и общий предел ожидания; пример не создаёт будущие запуски |
| channels | Отдельные enabled, permission_ref, провайдер и назначение каждой ветки |
| projects | Подтверждённая карта проектов и routes; конфликт требует уточнения |
| default_routes | Только согласованный маршрут по умолчанию; пустой массив не разрешает внешних действий |

Заполнять account_ref, contract_ref, destination_ref и permission_ref реальными проверенными ссылками/ID либо оставлять null. Не выдумывать рабочие инструменты или профили. Не класть токены, пароли и signed URL в JSON.

Для каждого впервые включаемого channels-направления сохранять собственный active_since. Для ранее настроенных направлений без этого поля применять прежнюю подтверждённую отсечку; не менять её и историю при донастройке. Поля setup_ref и automation дополняют schema_version=1: при старой конфигурации сначала проверить реальную настройку, затем добавить известные поля, сохранив остальные. Отсутствие нового поля не доказывает отсутствия действующего запуска.

Для projects использовать объекты: id, name, match_rules, routes. В match_rules хранить только подтверждённые правила, например source_title_exact, calendar_event_refs и organizer_refs. Правило source_title_exact применять только после согласования владельцем. Несколько совпавших противоречивых проектов → blocked, а не выбор первого. routes содержит имена настроенных channels.

Для внешнего отправителя проверить фактический авторизованный аккаунт; не брать автора скилла. Для own_tasks проверить профиль и место создания, обычный начальный статус и поддержку задачи без срока/проекта. Для API проверить контракт и все реальные последствия, включая публикации и создание задач.

## Включение направления

Пройти шаги 4–7 first-run.md: пробный результат, журнал и независимая ссылка, реальные запуски для автоматики, разрешение, активация и чтение итогового состояния. Сохранять только подтверждённые IDs/факты. Для внешних действий по команде не требовать расписаний. При недоступном направлении оставить конкретную блокировку и продолжить независимо готовые части.

Разовый запрос разобрать старую встречу не включает постоянный backfill. Отдельная команда отправить конкретную старую запись может разрешить ровно её; не распространять её на всю историю.

## Независимая ссылка

Создать личный bootstrap manifest по assets/bootstrap.example.json и зарегистрировать его bootstrap_ref в доступном постоянном контексте агента и каждом автоматическом запуске. Он хранит owner_ref, config_ref, state_ref и setup_ref. Проверять эту начальную точку до чтения настроек; ссылка на config внутри state и обратная ссылка на state внутри config не заменяют её.

При неудаче привязки указать в карточке, что настройки пока не подключены к следующим запускам. Не менять распространяемый SKILL.md ради сохранения личных ссылок и не считать память беседы устойчивым контекстом.

## Режим передачи

Передавать только файлы скилла и пустые примеры. Не включать рабочую конфигурацию, журнал, реальные транскрипты, адреса, токены, исходные письма, частные ссылки или историю разрешений. Каждый получатель начинает с REVIEW и своих подключений.
