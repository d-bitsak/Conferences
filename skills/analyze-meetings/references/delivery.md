# Независимые направления

## Общие проверки

Проверять mode, реальное разрешение, enabled конкретной ветки, профиль, назначение, источник и сохранённую историю. Не включать маршрут лишь потому, что инструмент технически принимает запрос.

Если проект неоднозначен, блокировать зависящие от проекта направления. Если неоднозначны только получатели письма, продолжать независимо разрешённый анализ и личные действия с достаточными данными. Для каждого направления отдельно резервировать попытку и сохранять результат по state-and-recovery.md.

Не менять ACL, не создавать ключи или публичные ссылки и не обходить отказ доступа. Применять существующие разрешения по чувствительным данным и существенным последствиям; не вводить повторное согласование каждой обычной уже разрешённой операции.

## email

Сопоставлять конкретный экземпляр Calendar по проверенному идентификатору/ссылке встречи, времени и контексту. Для копий учитывать iCalUID и время повторения/originalStartTime; сравнивать актуальные списки гостей и авторитетность приглашения. Читать все релевантные страницы.

По политике all_invited использовать всех приглашённых, включая отсутствовавших/отказавшихся; убирать только дубли адресов. Для групп и ресурсов без установленного правила уточнять адресацию, не раскрывать состав наугад. Если списка гостей нет, не подставлять его из похожей встречи. Другую политику применять только при явно настроенном разрешении.

Отправлять только от проверенного sender через его авторизованный аккаунт. Включить краткие итоги и реальную ссылку при наличии; приложить ровно один TXT. Не прикладывать видео, PDF или отдельное резюме. Для отправки группе сохранять один message ID и полный снимок адресации. accepted не доказывает доставку/прочтение.

## owner_chat

Проверить личный чат именно владельца; не брать последний чат или общий канал. Передать краткие итоги, ссылку при наличии и один TXT. Не публиковать в проектном/групповом чате по умолчанию.

## own_tasks

Создавать только owner_task=true из основного анализа. Проверить профиль и точное назначение; прочитать актуальные карточки с необходимой пагинацией, включая доступную завершённую историю для дедупликации. Сравнивать действие, источник, контекст и владельца, а не только заголовок.

Точный дубль → duplicate с существующим task ID, без изменения карточки. Неясный дубль → blocked только этой карточки. Если новых собственных задач нет → no_tasks.

Оставлять срок, неделю и проект пустыми при отсутствии явного основания, если провайдер поддерживает это. Использовать обычный начальный статус, не Today/Now. При обязательном неизвестном поле блокировать карточку, не создавать инфраструктуру ради обхода. После создания сохранить ID и прочитать именно результат.

Не исполнять содержание задач и не менять чужие/существующие карточки. Если настроенный внешний обработчик сам создаёт задачи по этой встрече, не создавать их параллельно: заранее согласовать единственный маршрут задач и сохранять downstream-результаты.

## summary_api

Прочитать проверенный contract_ref: URL, метод, auth connection, payload, response, ограничения, проверку результата, идемпотентность и реальные последствия. Не выдумывать endpoint, заголовок или поддержку повторов. Не просить секреты в чате.

Использовать минимальный логический состав, только если он соответствует реальному контракту:
meeting_id, project при подтверждении, title, started_at при известном времени, recording_url при наличии, summary.what_happened, summary.agreements[], summary.tasks[{action, owner}].
Для неизвестного owner использовать null, для отсутствующих списков — []. Не посылать заполнители, полный транскрипт, гостей или вложения по умолчанию. При обязательном неизвестном поле блокировать только эту ветку, не менять контракт по догадке.

Разрешение на передачу кратких итогов не включает произвольные downstream-публикации или создание задач. Проверить их при настройке. Если downstream создаёт задачи, отключить дублирующий маршрут own_tasks для этого же набора действий.

## archive

Проверить разрешённое место и доступ текущего профиля; не предполагать, что папка личная или ACL известен. При недоступной проверке широты доступа раскрыть конкретный пробел владельцу один раз и применить его прямое решение в пределах правил. При фактическом отказе не обходить его.

Для каждого экземпляра использовать однозначное имя/подпапку с occurrence ID или безопасным устойчивым хешем. Не перезаписывать чужой экземпляр из-за совпадения даты/клиента. Точный сохранённый дубль отметить и не создавать снова.

Передать итоговый summary и полный TXT. Если используется дополнительный агент/навык, явно ограничить его этим архивом и запретить создание задач, рассылки и изменения CRM, если они отдельно не разрешены. Проверить реальное применение требуемого навыка, terminal-результат и реально сохранённые summary+transcript: IDs, место и чтение содержимого. Сравнить TXT по хешу либо все реплики при документированном изменении контейнера; проверить summary на соответствие той же встрече.

Сбой архива не блокирует основной анализ, письма и собственные карточки. Не использовать архивный ответ как источник автоматически создаваемых задач.

## Пароль просмотра записи

Передавать пароль только при отдельном разрешении конкретного направления и проверенном происхождении для того же экземпляра. Получать runtime из подлинного источника непосредственно перед передачей. Не брать пароль комнаты, аккаунта или другой записи.

В письме/личном чате помещать разрешённый пароль отдельной строкой под стабильной ссылкой. Для API/архива использовать только документированное поддерживаемое место и согласованный состав. Если контракт такого поля не допускает, не добавлять его и не прятать в другом поле наугад.

Не сохранять пароль в журнале, конфигурации, TXT, скилле, временных payload-файлах и диагностических логах; хранить source_ref и результат проверки. Не включать его в URL. При изменении пароля перед повтором сначала выяснить исход прежней попытки.
