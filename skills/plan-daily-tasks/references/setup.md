# Личная конфигурация и адаптеры


Проводить диалог по first-run.md и завершать карточкой setup-result.md. assets/config.example.json и assets/source.example.json — пустые примеры, не доступы и не исполняемая программа. Рабочие экземпляры хранить в согласованном личном месте.

## Поля конфигурации


| Поле | Правило |
| --- | --- |
| mode | REVIEW по умолчанию; ACTIVE только для разрешённых проверенных изменений |
| owner_ref, timezone | Проверенная личность и IANA-зона; null не означает автора скилла или зону сервера |
| sources | Выбранные адаптеры, личность в каждом источнике и разрешённые области |
| calendars, calendar_enabled | Только выбранные календари/чтения; отсутствие подключения не доказывает отсутствие встреч |
| output_channel_ref | Проверенный личный разговор/канал; не новый чат на каждый запуск |
| permissions | Отдельные разрешения на источники, фокус/состояние, изменения и автоматику |
| selection.policy | focus_only по умолчанию; documented_today_update только в согласованной области |
| selection.write_source_ids | Источники, где разрешено соответствующее изменение; остальные остаются focus_only |
| state_ref, setup_ref | Операционные карты/снимки и отдельный manifest настройки |
| state_guard | Реальный способ исключительного резервирования перед внешним write; не требуется для чистого focus_only |
| automation | Фактические enabled, локальное время, ID запуска, назначение и начало; поля сами не создают запуск |
| bootstrap_ref | Независимая ссылка для нового контекста, не только внутри state/config |

Разрешённая источнику область не означает доступ ко всем проектам и другим системам. Для посредника/внешнего агента проверить разрешение общения, фактические вызовы и полноту; не считать его рассказ независимым доказательством и не передавать ему данные соседних систем.

## Адаптер источника


Для каждого рабочего источника заполнить копию source.example.json проверенными значениями:

| Поле | Смысл |
| --- | --- |
| id | Устойчивый локальный ключ источника для карт номеров |
| adapter_ref, account_ref, user_id | Реальный инструмент/подключение и проверенный ID владельца в этой системе |
| allowed_scope | Разрешённые проекты/области; не угадывать из доступности API |
| read_contract_ref, pagination_ref | Проверенные правила чтения и окончания страниц |
| status_mapping | Подтверждённые значения для представления; в карте сохранять также исходный raw_status |
| week_context_ref | Актуальный контекст недели только для поддерживающего её планировщика |
| today_mapping | Документированная операция, назначение и подтверждение смысла «на сегодня» |
| write | Отдельные enabled, permission_ref и проверенный write-контракт |

Не выводить today_mapping из похожего названия «Today», «Now» или недели. При отсутствии нужного read/write-инструмента указать точный предел. Не создавать инфраструктуру ради обхода обязательных полей.

## Независимая ссылка


Создать личный bootstrap manifest по assets/bootstrap.example.json с owner_ref, config_ref, state_ref, setup_ref. Зарегистрировать bootstrap_ref в доступном постоянном контексте этого агента; для расписания включить его в prompt. Перечитать контекст/prompt и открыть объекты по ссылкам без памяти беседы.

Искать сначала явный bootstrap_ref текущего запуска, затем постоянную привязку того же агента/владельца, затем явно переданную владельцем конфигурацию. Не сканировать чужие файлы и не брать настройки автора. Если ссылки нет, уточнить только привязку; существующую историю не заменять пустым примером.

## Режимы и разрешения


Для списка не требовать write-доступа. Для focus_only не менять карточки; сохранять выбор в согласованном личном состоянии либо в точном сообщении текущего разговора с оговоркой о восстановлении.

Прямая текущая команда может разрешить конкретное действие; не требовать повторного согласия. Постоянное изменение «после моего выбора переносить сюда» фиксировать с источником разрешения и точной операцией для каждого источника. Выполнение содержания задачи этим не разрешается.

Расписание создаётся только по отдельному прямому запросу. Проверять существующие запуски, зону, доступ к скиллу/источникам/состоянию и личную доставку. Автоматический список не является выбором и не меняет карточки. Дата включения расписания не фильтрует задачи по времени создания: давние незавершённые задачи в разрешённой области остаются кандидатами.
