# Карты, фокус и восстановление


Использовать одно согласованное личное состояние по assets/state.example.json. Не считать память чата устойчивым журналом и не включать рабочее состояние в распространяемый пакет.

## Структура


| Объект | Поля и смысл |
| --- | --- |
| lists | list_id, local_date, timezone, message_ref, read_at_utc, sources и items; неизменяемая карта выданного списка |
| sources внутри lists | source_id, read_at_utc, allowed_scope, pagination_complete, error; реальная полнота каждого источника |
| items внутри lists | number, source_id, provider_id, title, raw_status, project, verified_url; исходный номер не менять |
| morning_snapshots | snapshot_id, local_date, timezone, observed_at_utc, list_id, items; состояние «на сегодня» на момент подтверждённого утреннего чтения |
| focus_snapshots | snapshot_id, local_date, timezone, list_id, selection_message_ref, selected, unresolved_inputs, verified_at_utc; list_id верхнего уровня относится к последнему ответу, не ко всем ранее выбранным пунктам |
| selected внутри фокуса | source_id, provider_id, title, selection_refs, raw_status_before, raw_status_after, mutation_state; только понятная подтверждённая часть |
| selection_refs внутри выбранного пункта | list_id, number, source_message_ref, selection_message_ref; отдельное происхождение каждого добавления из конкретного списка |
| mutations | mutation_key, list_id, source_id, provider_id, intent, target, local_date, attempt_id, permission_ref, state, lease_expires_at, provider_result_ref, updated_at_utc; отдельный исход каждой операции |

Применять актуальное клиентское время в подтверждённой IANA-зоне. Если текущий локальный день не определён, не угадывать его по календарной дате сервера и не применять выбор к произвольному дню.

## Карта и снимки


Выданный список неизменяем: новая сортировка, чтение или день создают новый list_id. Ответ связывать с исходным message_ref/list_id, не с похожими заголовками. При нескольких подходящих картах уточнить одну привязку. Если внешняя запись сообщения не вернула ID, сохранить доступную точную ссылку/идентификатор контекста; не выдумывать ID.

Фокус можно дополнять, сохраняя ранее выбранное, если пользователь не попросил заменить/исключить. Утренний снимок не переписывать результатом вечера. Позднее чтение не называть утренним, если нет соответствующего источника/времени. При отсутствии утреннего плана прямо обозначать пробел.

При добавлении из другого списка сохранять собственные selection_refs каждой выбранной карточки. Объединять повторный выбор одной source_id/provider_id в один пункт, добавляя происхождение; разные карточки с одинаковым номером не сливать. В показе фокуса при совпадающих исходных номерах указывать также дату/список, не выдавать один общий list_id за происхождение всех пунктов.

Если личного хранилища нет, использовать точное датированное сообщение с картой и объяснять ограничение следующей сессии. Невозможность сохранить карту не даёт права угадать номера. При невозможности установить источник ответа уточнить его до зависимых действий.

## Внешние изменения


Для каждой карточки сохранять prepared, reserved, accepted, verified, unknown, blocked либо failed с фактическими ID и исходом. Эти состояния не заменяют raw_status провайдера. Согласованный focus_only фиксировать без внешнего изменения, а не как успешный перенос.

До изменения перечитать карточку, проверить профиль, разрешение, mapping и исход прошлой попытки. Если желаемое состояние уже есть, новый вызов изменения не нужен. При прежнем unknown различать подтверждённое текущее состояние карточки и неизвестность исполнения исходного вызова; не придумывать provider ID принятия.

До внешнего write успешно сохранить reserved конкретной операции через реальную expected version/CAS либо удерживать подтверждённое исключительное владение на всём интервале «проверка → вызов → фиксация». Стабильный mutation_key определять по владельцу, source_id/provider_id, намерению, целевому состоянию и дню применения; новый список/ответ не даёт новый ключ для обхода unknown. Сохранить attempt_id и срок владения, перечитать подтверждение резерва. Только после этого выполнять внешний вызов.

При конфликте резерва перечитать и пересчитать; не вызывать API по старому снимку. Живую чужую попытку не перехватывать. Истечение владения не доказывает отсутствие эффекта: сначала сверить прошлый исход. Обычная запись состояния после двух уже выполненных вызовов не является защитой. Если надёжного резерва нет, остановить только изменения, продолжить фокус.

После ответа немедленно сохранить provider result и прочитать карточку. accepted без проверки не называть подтверждённым изменением. При тайм-ауте/потере ответа ставить unknown и сначала выяснять прежний исход. Не повторять вслепую и не менять ключ для обхода unknown. Завершённую карточку не открывать снова ради выбранного сегодня номера.

При ошибке сохранения уже полученного результата удержать известный provider result в разрешённом постоянном контексте/сообщении и восстановить журнал без повторного изменения карточки. Не заявлять долговременное сохранение до проверки.

Изменение названия или текста задачи не означает новую карточку. Новое сообщение пользователя не отменяет уже подтверждённый исход. Не обещать exactly-once между внешней системой и личным журналом.

## Возобновление


Находить bootstrap_ref текущего запуска или постоянного контекста своего агента, проверять владельца и читать config/state/setup. Явная личная ссылка владельца допустима как начальная точка. Не искать файлы по памяти беседы и не сканировать все доступные папки.

Продолжать по конкретной карте и операциям. При ответе на прошлый день спросить день применения, не копировать молча старый фокус. Текущий календарь можно показать независимо с датой. При недоступном источнике сохранять подтверждённую часть и конкретный пробел, не блокируя другие источники.
